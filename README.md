| --- | --- | --- | --- |
| 115网盘STRM助手 | 2.8.74.3 | [DDSRem](https://github.com/DDSRem) | 修复整目录转存子文件延迟可见导致漏整理，增加有界复扫和停止后的持久化恢复 |
| 115网盘储存 | 3.0.3 | [DDSRem](https://github.com/DDSRem) | 修复并发限流等待不断增长、移动后重命名及文件状态核验；要求 MoviePilot V3 |
| 115网盘订阅追更 | 1.5.8 | [mrtian2016](https://github.com/mrtian2016) | 每轮同步以媒体库真实缺失回写订阅进度，修正"已订阅集数"显示不准（删除剧集/重置订阅后自动校准） |
| Emby媒体库封面生成 | 1.0.2 | [Kioo / wio-ki](https://github.com/wio-ki) | 后台合并处理入库事件，背景图失败回退海报；要求 MoviePilot V3 |

在 MoviePilot 插件市场添加此仓库地址：

```text
https://github.com/zoom521241/MoviePilot-Plugins
```

当前沿用 `package.v2.json` 和 `plugins.v2/` 布局。MoviePilot V3 可通过兼容索引发现这些插件；储存插件声明 `system_version >=3.0.0`，使用 V3 SDK。STRM 助手保留旧版本分支，本次验证在 V3 完成。

## 本次修复

### 115网盘订阅追更 1.5.8（2026-09-24）

修复订阅页「已订阅集数」显示不准。该数字是派生值 `total_episode - lack_episode`（见 `app/schemas/subscribe.py` 的
`compute_subscribe_completed_episode`），而 MoviePilot 只在「总集数变化 / 下载事件 / 洗版」等时机回写 `lack_episode`，
**删除剧集、重置订阅都不会与影视库对账**。插件此前在转存成功后用自己的 `note`（只记录插件自己转存过的集）反推缺失集数写回，
于是出现绿灯军团 Emby 实际已有 6 集、订阅页却显示 1 集的情况。

1.5.8 的修复方式：

- **每轮同步对账**：取到 `get_no_exists_info`（媒体库口径）后，调用 `sync_lack_episode_with_library()` 把 `lack_episode`
  校准为媒体库真实缺失集数，删除剧集或重置订阅后下一轮同步自动纠正（延迟不超过一个同步周期）。
- **不再用 note 反推**：`check_and_finish_subscribe()` 新增 `library_lack` 参数，有媒体库数据时以它为准；
  「是否完成订阅并移入历史」仍按原有 note 覆盖率规则判断，避免行为回归。
- **修正陈旧值导致的跳过**：原先 `lack_episode == 0` 会直接跳过订阅，而该字段可能未与影视库对账，现改为继续核对媒体库。
- 未播出的剧集在 `no_exists` 中同样计入缺失，因此不会误算成 0 而误触发订阅完成。
- 新增 13 项离线回归测试（仓库总计 142 项通过）。

部署验证：2026-09-24 在 MoviePilot V3 / PostgreSQL 环境热重载后手动触发同步，日志出现
「校准订阅 绿灯军团 S1 缺失集数（以媒体库为准）：7 -> 2」，与 Emby 实际拥有 E01-E06 一致，订阅页显示 6 集。

### 115网盘订阅追更 1.5.7（2026-09-23）

修复 V3 近期版本将 `get_no_exists_info` 返回字典的键改为来源前缀格式（如 `tmdb:95350`，见 `app/schemas/media.py` 的 `build_media_key`）后，插件仍按裸 tmdb/douban id 查键，导致剧集订阅每次都查不到缺失集、被误判为「没有缺失剧集信息」而整体跳过搜索的问题。实际后果：绿灯军团 S01E06 本地文件被删除、订阅重置后，插件连续多次同步（02:30/10:30/18:30 及手动触发）均跳过该剧，不再搜索 115 资源。

1.5.7 将键解析抽为 `resolve_no_exists_season_info`：依次尝试裸 id、字符串 id、`tmdb:/douban:` 前缀键，并在字典仅单键时兜底取用（调用方始终针对同一媒体查询，单键必然属于当前媒体）。新增 8 项回归测试（仓库总计 131 项通过）。



### 115网盘订阅追更 1.5.6（2026-09-21）

补齐 MoviePilot V3 显式数据库 Session 的事务提交。此前 `SubscribeOper(db=db).update(...)` 只修改当前事务，退出 Session 不会自动提交，导致日志称“已更新”但新站点限制未保存。排除名单为空时，《生化危机：爆发夜》虽然由插件搜索 115 资源，站点仍为 `null`，系统可使用默认 PT 站点；这不是被用户排除。

- 批量屏蔽、窗口恢复、新增订阅和主插件兜底写入均在返回成功前提交事务；提交失败不记录批量成功。
- 排除模式处理所有未勾选排除的订阅，指定模式只处理勾选的订阅；电影和电视剧使用相同过滤规则。排除项保留自身站点设置。
- 保留 1.5.5 的虚拟站点域名与 RssSites 交集修复，不改搜索顺序、Cookie 或 PT 放行窗口。
- 新增真实 SQLite 事务回归，验证退出会话后数据持久化、异常回滚以及排除/指定模式。

部署验证：2026-09-21 在 MoviePilot V3 / PostgreSQL 环境热重载后，7 个未排除订阅的 `sites` 均实际保存为 `[-1]`，包括此前为 `null` 的电影订阅；运行目录与本地插件源代码一致。订阅回归测试 28 项通过。当前排除列表为空、PT 放行站点为空，因此始终保持系统订阅屏蔽。

### 115网盘订阅追更 1.5.5（2026-09-21）

修复 MoviePilot V3 下「系统订阅屏蔽」被绕过的问题。此前版本把纳管订阅的 `sites` 改写为仅 `115网盘`（站点 id=-1）来屏蔽系统订阅，但 V3 的 `get_sub_sites()`（`app/chain/subscribe/query.py`）在订阅站点与系统默认订阅站点（RssSites）**交集为空时，直接回退为全部默认站点**，导致"仅115"变成"搜索全部真实 PT 站"。实际后果：绿灯军团 S01E06 在插件转存窗口（cron 10:30）到来前，被 V3「站点资源缓存 + 订阅资源检查」服务于 09:12 从 PT 站抢先下载入库。

1.5.5 的修复方式（会更新全局 RssSites，保留原有真实 PT 站点）：

- **屏蔽态把 115 站点(-1) 并入系统 RssSites**：交集变为 `[-1]`，非空，V3 不再回退；订阅搜索与站点资源缓存匹配两条路径同时恢复屏蔽。解除屏蔽时反向移除 -1（原 V3 下此逻辑是静默空操作，已改为通过 `self.systemconfig` 正确读写）。
- **补齐 115 虚拟站点的 `domain='115.com'`**：原为空导致订阅缓存匹配按域名过滤时失效。
- **同步任务自愈**：每次同步任务（默认 02:30/10:30/18:30）运行时重新断言合并，防止 RssSites 被其他操作改动后屏蔽再度失效。
- 新增 16 项离线回归测试（仓库总计 111 项，`python -m unittest discover -s tests -v` 全部通过）。

实际部署于极空间 NAS 的 MP V3 容器验证：运行版本 1.5.5、RssSites=`[-1,1,2,4,7,8]`、site -1 domain=`115.com`、纳管订阅 sites=`[-1]`。

### 历史修复

STRM 助手 2.8.74.3 修复直连 115 整目录转存时，生活事件先到、子文件列表稍后才完整可见导致漏整理的问题。目录整理先收集文件，每轮扫描后间隔 10 秒复扫；至少观察 30 秒，且连续两次完整比较的文件 ID、路径和必要属性均不变，才确认稳定。提交整理前按文件 ID 合并各轮有效结果，避免边扫描边移动影响后续分页。单文件整理和 CloudDrive2 路径沿用原有流程。

扫描最多 6 轮，并设 120 秒软时限；等待受剩余时限约束，单次网络请求另设超时，已经阻塞的请求不能由总时限立即中断。达到上限仍未稳定时，只提交已发现的有效文件，并将记录保留为 `needs_review` 待核查；持续扫描错误或提交失败同样不会触发无限自动重试。

目录事件和 MoviePilot 已受理的文件 ID 保存在插件数据中。扫描或提交期间停止后，下次启动会恢复未完成目录并跳过已受理文件；进程退出留下的进行中记录也会恢复。恢复独立于生活事件游标，即使选择 `latest` 模式也会执行；目录位置或监控范围变化时保留待核查记录。

STRM 助手原有异步整理接管绕过 V3 的持久化任务结算，会让恢复线程重复提交同一任务。检测到 V3 整理链时，现在交由宿主原生流程执行，并继续使用插件发现文件和生成 STRM。停止队列后不再提交剩余批次。

储存插件在云盘移动成功后使用稳定的文件 ID 完成重命名，避免依赖尚未更新的路径查询。目录 ID 统一按整数处理，防止将非根目录误判为根目录；严格存在性查询读取远端状态，网络错误仍按未知状态处理。

3.0.3 将限流时间采样移入锁内，修复并发时等待从 2 秒增长为 4、8、16 秒等的问题，保留原有调用频率限制。回归测试用真实线程和虚拟时钟验证等待时间与配额。

封面插件将入库事件交给可停止的后台队列，同一批次、同一媒体库合并生成。Emby 无法下载远程背景图时，回退同一媒体项的海报；停止任务后取消待处理事件和后续上传。原有配置和样式保持兼容。

此前的 V3 兼容修复已实测复制一个视频到监控目录，自动整理完成移动、重命名及 STRM 生成；另一个先前失败的视频重试成功。直接查询云盘确认文件大小、SHA1 和目标目录正确，整理及重试队列正常收口。2.8.74.3 新增目录收集逻辑通过离线测试验证列表增长、属性变化、异常、时限和停止行为。回归测试可运行：

```sh
python -m unittest discover -s tests -v
```

## 更新与持久化

拉取 Docker 新镜像不会直接修改正在运行的插件。重建容器时应保留原 `/config` 挂载；新版宿主的恢复流程和接口兼容性仍需确认。插件升级或重装会替换代码，应从包含本次修复的来源安装。

仓库推送不会自动切换现有安装的插件来源。在 MoviePilot V3 的插件来源选项中明确选择本仓库，刷新市场后安装对应版本；仅覆盖运行目录不能保证容器重建后仍使用修复版。保留 `/config` 挂载和本仓库来源绑定，可从这里重新安装。未来宿主或 115 接口变化仍可能需要新的兼容补丁。
